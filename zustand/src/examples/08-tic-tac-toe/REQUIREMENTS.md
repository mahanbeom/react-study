# Tic Tac Toe — 요구사항

공식문서 [Tutorial: Tic-Tac-Toe](https://github.com/pmndrs/zustand/blob/main/docs/learn/guides/tutorial-tic-tac-toe.md)

## 무엇을

3×3 틱택토. 두 사람이 번갈아 두고, 지나간 수로 되돌아갈 수 있다.

## 왜

새로운 zustand API는 하나도 나오지 않는다. 01~07에서 배운 것(스토어 설계, selector,
불변 갱신, 파생 값)을 **빈 파일에서 조합해내는** 게 목적이다.
특히 되돌리기(history)가 불변 갱신을 강제한다 — mutation을 한 번이라도 하면 과거 기록이 오염된다.

## 완료 기준

기능:

- [x] 3×3 보드. 빈 칸을 누르면 현재 차례의 기호가 놓인다
- [x] X와 O가 번갈아 둔다 (X 선공)
- [x] 이미 채워진 칸을 누르면 아무 일도 일어나지 않는다
- [x] 승부가 난 뒤에는 더 둘 수 없다
- [x] 상태 표시: `Next player: X` / `Winner X` / `Draw`
- [x] 지나간 수 목록. 누르면 그 시점으로 되돌아간다 (0번은 "게임 시작")
- [x] 과거로 되돌아간 뒤 새로 두면, 그 이후의 기록은 버려진다

품질:

- [x] 스토어의 배열을 직접 수정하는 코드가 없다 (mutation 금지)

## 설계 힌트 (막히면 볼 것)

### 상태에 무엇을 둘까

공식 튜토리얼의 최종 상태는 **두 개뿐**이다.

```
history: string[][]   // 각 시점의 보드. 초기값은 [빈 보드 하나]
currentMove: number   // 지금 보고 있는 시점의 인덱스
```

`xIsNext`는 상태로 두지 않는다. `currentMove % 2 === 0`으로 **계산**할 수 있기 때문이다.
튜토리얼이 "Final cleanup"에서 일부러 제거한다 — 중복 상태는 버그의 원천이다.
05의 `getBoth`가 상태 없이 파생 값을 만들던 것과 같은 판단이다.

승자도 마찬가지다. 보드에서 계산할 수 있으므로 상태로 저장하지 않는다.

### mutation을 조심할 곳

- `squares[i] = 'X'` — 금지. `slice()`로 복사한 뒤 그 복사본을 고친다(local mutation),
  또는 `map` / `toSpliced`를 쓴다.
- 새 수를 둘 때 history 자르기 — `history.slice(0, currentMove + 1).concat([next])`.
  `slice`와 `concat`은 새 배열을 반환하므로 안전하다. `push`는 mutation이다.

### 승자 판정

가로 3 · 세로 3 · 대각선 2 = 8줄을 검사한다. 스토어 밖 순수 함수로 두면 테스트하기 쉽다.

```
[0,1,2] [3,4,5] [6,7,8]   // 가로
[0,3,6] [1,4,7] [2,5,8]   // 세로
[0,4,8] [2,4,6]           // 대각선
```

### 공식 튜토리얼과 다르게 갈 부분

튜토리얼은 `combine` 미들웨어를 쓴다. 아직 안 배웠으므로 **지금까지 쓰던
`create<T>()((set) => ({ ... }))` 형태로 쓴다.** 결과는 같다.
`combine`은 Reference의 미들웨어 섹션에서 다룬다.

#### 측정 기록 (StrictMode 라 2씩 오른다)

**빈 칸 하나를 놓았을 때** (칸 0 클릭)

| 대상 | Square 가 보드 전체 구독 | Square 가 자기 칸만 구독 |
| --- | --- | --- |
| 누른 칸 | 2 → 4 | 2 → 4 |
| 나머지 8칸 | 2 → **4** | 2 → **2** |
| Status | 2 → 4 | 2 → 4 |
| MoveList | 2 → 4 | 2 → 4 |
| Board | 2 → 2 | 2 → 2 |
| TicTacToe(최상위) | 2 → 2 | 2 → 2 |

**승부가 나는 수를 놓았을 때** (X 가 0·1·2 로 가로 완성)

| 칸 | 전 → 후 | 이유 |
| --- | --- | --- |
| 0 | 4 → 6 | `isWinning` false→true |
| 1 | 4 → 6 | `isWinning` false→true |
| 2 | 2 → 4 | 값과 `isWinning` 이 같은 렌더에서 함께 |
| 3, 4 | 4 → 4 | O 가 놓인 칸. 변화 없음 |
| 5~8 | 2 → 2 | 한 번도 바뀐 적 없음 |

Board 와 최상위가 2 로 고정인 것이 핵심이다. 부모가 리렌더되면 자식은 props 가 같아도
따라 리렌더되므로, 구독을 아무리 잘게 나눠도 소용이 없어진다.

주의: 리렌더가 걸러지는 것이지 selector 실행이 걸러지는 게 아니다.
스토어가 바뀌면 9칸의 selector 가 모두 실행되고, 결과가 달라진 칸만 리렌더된다.
